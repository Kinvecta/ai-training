[21:07] lifecycle
Y todo cabe en un solo ciclo DevSecOps. Mira cómo da la vuelta. Diseño: pocas herramientas, esquemas estrictos y un modelo de amenazas, revisado. Construcción: con el kit de la versión dos, validando cada entrada, para que el esquema rechace la entrada inválida. Pruebas: pruebas unitarias, el Inspector y la ruta de rechazo, para que un no deje el ticket abierto. Seguridad: autorización, audiencia del token revisada, nunca reenviado, y acceso mínimo. Publicación: una imagen de contenedor escaneada y firmada, más un punto de control que compara la lista de herramientas con el snapshot. Operación: logs, auditoría, límites de uso y una alerta cada vez que cambia la lista de herramientas. Y de ahí regresa al diseño. Versiona el servidor como una API. Quitar o renombrar una herramienta es un cambio mayor. Una herramienta nueva es un cambio menor. Un parche nunca cambia la lista de herramientas. Marca como obsoleto antes de borrar. Seguridad en cada paso, no al final.
